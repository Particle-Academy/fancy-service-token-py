# AGENTS.md — fancy-service-token-py

The Python leg of the Fancy service-token set: a verifier for `fst1` tokens plus
ASGI middleware. `CLAUDE.md` points here. Process rules (publishing, versions,
backports) live in the envelope's `RULES.md`, not here.

Siblings, held to the same fixture file: `fancy-service-token` (PHP, the
signer and a verifier) and `fancy-service-token-js` (Node verifier).

## Where things are

- `src/fancy_service_token/_token.py`: `Verifier`, `Key`, `Claims`, `Verdict`,
  `Reason`, `ReplayStore`, `MemoryReplayStore`. The format and the order of
  checks are in the README; the code follows that order step by step.
- `asgi.py`: `ServiceTokenMiddleware`, `current_request_id`, `RequestIdLogFilter`.
- `depends.py`: `service_token_claims`, the only module that imports Starlette.
- `conformance/service-token-v1.json`: the shared fixtures. Generated by
  `scripts/build_fixtures.py` from raw `hmac`, never from this package.
- `tests/sabotage.py`: the mutation sweep CI runs.

## Invariants a change must keep

- **Zero runtime dependencies.** Standard library only: `hmac`, `hashlib`,
  `base64`. No JWT library, no cryptography beyond HMAC-SHA256.
- **Refuse before the body.** The middleware decides from `scope["headers"]`
  and never calls `receive()` or the app on a refusal. Verification must stay in
  middleware: FastAPI reads a body before it resolves dependencies.
- **The order of checks is the contract.** It decides which reason a token wrong
  in two ways gets, and the PHP and Node legs are held to it by the fixtures. A
  nonce is spent only after every other check passes.
- **Constant-time** comparison of the signature (`hmac.compare_digest`), and an
  HMAC is computed even for an unknown key id.
- **Strict parsing.** Canonical unpadded base64url only, ASCII only, bounded
  lengths checked before anything else, character-class checks rather than
  regular expressions on hostile input.
- **Nothing secret leaves.** No token, secret, nonce or exception text in a
  response or a log line; exceptions are logged by class name. `Key.secret` and
  `Claims.nonce` are excluded from `repr`.
- **Fail closed.** `verify()` never raises; an unexpected error is `malformed`.
  A full replay store refuses. `service_token_claims` without the middleware
  refuses.
- The `Reason` values are a fixed public contract. Adding one is a breaking
  change for every leg.

## Changing the fixtures

Edit `scripts/build_fixtures.py`, run it, then copy
`conformance/service-token-v1.json` byte for byte into the PHP and Node repos
and update the pinned SHA-256 in all three suites (`tests/conftest.py` here).
The file is `-text` in `.gitattributes`, so no checkout rewrites its line
endings.

## Tests

`pytest` (`tests/asgi.py` is a small ASGI driver, so no HTTP client is needed),
`ruff check . && ruff format --check .`, `mypy`, then `python tests/sabotage.py`.
